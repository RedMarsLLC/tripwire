# Collector APIs, permissions and visibility

The implementation uses public frameworks or documented read-only utilities, never a custom kernel module, private framework, direct TCC database reader, security-control bypass or unsupported socket structure. The overlay also reads the version-dependent, read-only XNU `kern.memorystatus_vm_pressure_level` diagnostic for current memory pressure; unknown formats/access failures remain explicitly unavailable. OS/collector build metadata accompanies events. Diagnostic text formats can change; parsers reject unrecognized rows instead of claiming a complete inventory.

Signing metadata uses `SecStaticCodeCreateWithPath` and `SecCodeCopySigningInformation`. Presence of metadata is explicitly labeled as **not a full validity check** and never establishes benign behavior. A missing Team ID can occur for platform/ad-hoc/unsigned code and is not a malicious verdict.

## Endpoint Security version guards

Verified directly against the installed SDK's `EndpointSecurity/ESMessage.h` and Apple documentation. `seq_num` is per client/per event type and is available when `message.version >= 2`; `global_seq_num` is per client and available when `message.version >= 4`. Tests cover versions 0, 1, 2, 3 and 4. Tracker input must be serialized before async reordering. A forward discontinuity records the missing count; duplicate/backward sequence means uncertain continuity. The first observed number is not enough to prove earlier loss. Reset the tracker for each new ES client. An unavailable client cannot report zero loss.

Local AI-app resource sampling uses public libproc process metadata/rusage counters with bounded enumeration, exact bundle path and parent matching, PID/start checks and explicit partial visibility. It measures local CPU/RAM, not cloud inference or causation of host changes. Private process structures are not used. Sources disclose provenance, errors, time semantics and completeness independently of their data.

## AI open-file snapshots

The `ai-open-files` source recognizes running Codex, ChatGPT, Claude, Cursor, Ollama and LM Studio desktop apps using the same discovery as local resource sampling. Exact bundle-path boundaries seed association, extended through observed parent links only when the parent predates the child. PID, start time, executable and parent are checked again for every ancestry node after descriptor sampling; reused/reparented processes lose the association. Recognition is heuristic, not signature attestation. Standalone CLI agents without a visible recognized ancestor are outside scope.

Sampling uses up to 4,096 current-user PIDs, 128 matched processes, 4,096 descriptors per process and 2,048 distinct file/process/mode records per pass, with a cooperative 1.5-second process-loop budget. Truncation, process races and denied descriptor queries leave scope partial. Unknown/empty failures stay unknown. Read/write flags describe descriptor capability; event-only handles are distinguished. No offset, file bytes, process arguments or environment values are collected. Vnode path buffers that appear truncated or invalid are rejected. Snapshots cannot prove deletion, close, actual I/O, continuous access or absence, and never emit removal events.

The file loop is independent of general inventories and overlay visibility. Checks pause about two seconds after each completed sample; the interval is not a delivery guarantee. File Activity and the overlay mark file status stale after ten seconds and long check intervals record a gap. No loss count is inferred. Collection ends when foreground monitoring ends; it does not continue after app exit. Historical rows are labeled last observed; **Latest check only** means the last recorded sample, including when stopped.

Files held in the current user's `.ssh`, `.aws`, `.azure`, `.config/gcloud`, `.kube`, `.gnupg`, or `Library/Keychains`; system/user LaunchAgents, system LaunchDaemons, selected shell startup files, and `/Library/Extensions` or `/Library/SystemExtensions` receive sensitive-location findings. Path boundaries are exact and lexical; no target content is inspected. Findings apply on initial and partial observations and retain source limits, association basis and unknown intent. They are review prompts, not proof of misuse. All other observed files remain inspectable without automatically becoming findings.

A complete event audit still needs a separate NOTIFY-only Endpoint Security adapter and an approved deployment. No entitlement, permission, root helper or installation is fabricated by this snapshot source.
